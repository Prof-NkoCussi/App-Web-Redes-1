19. TCP y UDP

Dos formas de llevar los datos

La capa de transporte (capa 4 del modelo OSI, TP3) lleva los datos de una aplicación a la aplicación correcta del otro dispositivo, con TCP o con UDP.

Comparación entre TCP y UDP
AspectoTCPUDP
Orientación a conexiónSí: primero se conectaNo: envía sin conectarse
ConfiabilidadAlta: confirma, reenvía lo perdido y ordena los datosBaja: no confirma ni reenvía
VelocidadMenor: más controlesMayor: casi sin controles
Control de flujoSí: el receptor avisa cuánto puede recibirNo

Handshake de tres pasos

Casos de uso típicos

  • TCP: cuando todo tiene que llegar completo. Descarga de un archivo, email, páginas web.
  • UDP: cuando importa más la rapidez que perder un dato. Videollamada, juego online, streaming en vivo, consulta DNS.

Idea clave: TCP es confiable pero más lento; UDP es más rápido pero no confirma la entrega.

20. Puertos

Cada aplicación tiene su número

Un puerto es un número del 0 al 65535 que identifica a una aplicación dentro de un dispositivo. La IP dice a qué dispositivo van los datos; el puerto, a qué aplicación.

Ejemplo

La IP es como la dirección de un edificio, y el puerto, el número de departamento.

IP + puerto

Se escribe
IP:puerto

  • Cliente: tu PC

    192.168.1.25:51234
    El navegador usa un puerto dinámico.

  • Servidor web

    203.0.113.10:443
    Atiende HTTPS en el puerto 443.

Cada servicio usa su puerto y su protocolo de transporte: HTTPS, el 443 con TCP; DNS, el 53 con UDP.

Tres rangos de puertos

  • Bien conocidos

    0–1023

    Servicios estándar: 80 (HTTP), 443 (HTTPS), 53 (DNS).

  • Registrados

    1024–49151

    Aplicaciones conocidas: 3306 (MySQL).

  • Dinámicos

    49152–65535

    Los elige el cliente para cada conexión.

Idea clave: la IP encuentra el dispositivo, y el puerto, la aplicación.

21. DNS y DHCP

Traducir nombres y repartir IP

Desde esta lámina vemos protocolos de aplicación: trabajan en la capa de aplicación (capa 7 del modelo OSI, TP3). Cada uno usa un puerto y viaja con TCP o con UDP.

DNS

Puerto53UDP

El DNS (sistema de nombres de dominio) traduce un nombre en la IP del servidor: www.redesdelaula.com → 203.0.113.10. Funciona como la agenda del celular: buscamos un nombre y obtenemos el número.

  1. 1La PC busca el nombre en su caché.
  2. 2Si no está, le pregunta a su servidor DNS (8.8.8.8).
  3. 3Si el servidor DNS no la sabe, les pregunta a otros servidores DNS hasta conseguir la IP.
  4. 4Le responde la IP a la PC, y la PC la guarda en su caché.

La caché guarda las respuestas un tiempo: la próxima vez, la IP sale enseguida, sin preguntar. Probalo en el simulador DNS, después de esta lámina.

DHCP

Puertos67 y 68UDP

En el TP4 vimos que la IP puede ser estática o dinámica. La dinámica la asigna un servidor DHCP (en casa, suele ser el router) cuando el dispositivo se conecta a la red. Lo hace en cuatro pasos, el proceso DORA:

  1. DDiscover (descubrir): la PC pregunta a toda la red si hay un servidor DHCP.
  2. OOffer (ofrecer): el servidor le ofrece una IP, por ejemplo 192.168.1.25.
  3. RRequest (solicitar): la PC pide usar esa IP.
  4. AAcknowledge (confirmar): el servidor confirma, y la IP es de la PC por un tiempo.

Además de la IP, la PC recibe la máscara (255.255.255.0), la puerta de enlace (gateway, 192.168.1.1) y el DNS (8.8.8.8). El servidor usa el puerto 67, y la PC, el 68.

Idea clave: DNS traduce nombres en IP; DHCP le da a cada dispositivo su IP al conectarse. Los dos usan UDP.

22. HTTP y HTTPS

Pedir y recibir páginas web

HTTP

Puerto80TCP

HTTP es el protocolo de la web: el navegador (el cliente) le envía una solicitud al servidor web, y el servidor le contesta con una respuesta. Antes, el navegador consigue la IP con DNS (lámina 21) y se conecta con el handshake de TCP (lámina 19).

La solicitud · del navegador al servidor

HTTP
GET /index.html HTTP/1.1
Host: www.redesdelaula.com
User-Agent: Mozilla/5.0 (Windows…)
Accept-Language: es-AR
  • Método: GET pide una página.
  • URL: se arma con el Host y la ruta: http://www.redesdelaula.com/index.html
  • Headers: datos extra, uno por renglón: el sitio, el navegador y el idioma.

La respuesta · del servidor al navegador

HTTP
HTTP/1.1 200 OK
Content-Type: text/html

<!DOCTYPE html>…
  • Código de estado: cómo salió el pedido; 200 OK es “todo bien”.
  • Headers: datos extra, como el tipo de contenido.
  • Contenido: la página, escrita en HTML.

Códigos de estado

  • 200OKSalió bien.
  • 301Moved PermanentlySe mudó a otra URL.
  • 403ForbiddenProhibido: no se puede ver.
  • 404Not FoundNo existe esa página.
  • 500Internal Server ErrorFalló el servidor.

HTTPS

Puerto443TCP

HTTPS es HTTP cifrado: nadie en el medio puede leer ni cambiar lo que viaja.

Importante

Nunca escribas una contraseña sin el candado de HTTPS.

Idea clave: en HTTP, el cliente envía una solicitud y el servidor devuelve una respuesta con un código de estado.

23. FTP, SSH y correo

Archivos, acceso remoto y mensajes

FTP

Puertos20 y 21TCP

FTP (protocolo de transferencia de archivos) sirve para subir y bajar archivos de un servidor con un programa de FTP. Usa el puerto 21 para las órdenes (control) y el 20 para los datos. No cifra: los archivos y la contraseña viajan sin protección.

Ojo: descargar un archivo desde una página web no usa FTP, sino HTTP o HTTPS.

SSH

Puerto22TCP

SSH (en inglés, Secure Shell) permite manejar la terminal de otra computadora a distancia: es un acceso remoto. Todo viaja cifrado, también la contraseña.

Se usa, por ejemplo, para administrar un servidor sin estar frente a él.

Correo electrónico (email)

Los tres
usan TCP

  1. Remitente

    Envía el correo con SMTP (puerto 25).

  2. Su servidor de correo

    Lo reenvía con SMTP (puerto 25).

  3. Servidor del destinatario

    Lo guarda en el buzón.

  4. Destinatario

    Lo recibe con POP3 (110) o IMAP (143).

  • POP3 · puerto 110

    Descarga los correos a un dispositivo y, por lo general, los borra del servidor. Lo que bajó la notebook no aparece en el celular.

  • IMAP · puerto 143

    Deja los correos en el servidor y sincroniza: lo que leés o borrás en el celular se ve igual en la notebook.

Idea clave: FTP transfiere archivos; SSH da acceso remoto cifrado; el correo usa SMTP para enviar y POP3 o IMAP para recibir. Todos usan TCP.
